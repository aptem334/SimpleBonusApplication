# T-006 — Интеграционные тесты: сценарная таблица

**Status:** done
**Priority:** medium
**Component:** docs

## Контекст
Юнит-тесты покрывают состояния, но не покрывают сквозной сценарий «несколько покупок подряд
с пересчётом баланса». Именно там обычно и живут дефекты округления и накопления.

## Требование
Таблица сценариев «канал + сумма → ожидаемые бонусы, комиссия, балансы»,
покрытая интеграционными тестами через MockMvc, включая последовательные покупки.

## Критерии приёмки
- [ ] Таблица сценариев лежит в `docs/DOMAIN.md` и покрыта тестами 1:1
- [ ] Есть кейсы: 15.00 Shop (бонус + комиссия), 19.99, 20.00, 299.99, 300.00, 300.01, 400.00
- [ ] Есть кейс последовательных покупок с накоплением бонуса
- [ ] Проверяется округление на «некруглых» суммах
- [ ] `./mvnw clean verify` зелёный

## Решение / резолюция
Сделано. 23 интеграционных теста через MockMvc.

В `docs/DOMAIN.md` добавлена **сценарная таблица** — 13 строк с точными числами, на которые
ссылается `PaymentApiTest.purchaseScenario`. Таблица и тесты обязаны двигаться вместе:
новое правило без строки в таблице — неполное правило.

Отдельно отмечено в DOMAIN.md три строки, которые обязаны различаться
(`Shop 300.00`=30.00, `Online 300.00`=51.00, `Shop 300.01`=90.00): если они слипнутся,
ослеп тест, а не сломалась логика.

Проверены округление на некруглых суммах, накопление при последовательных покупках
и нехватка средств с учётом комиссии (20.00 на счёте не покрывают покупку 19.00 + 1.90).
