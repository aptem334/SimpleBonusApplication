# Доменные правила — source of truth

Если код противоречит этому документу — баг в коде.
Если этот документ противоречит бизнес-требованию — баг в документе, нужен тикет.

## Счета клиента

| Счёт | Что это | Меняется |
|---|---|---|
| `money` | наличные / безнал | −`amount` при покупке, −комиссия |
| `bonus` | бонусный счёт (e-money) | +бонус при покупке |
| `bankCommission` | накопленная комиссия банка | +комиссия при покупке |

Начальные значения задаются в `application.yml` (`app.initial.*`), а не хардкодятся.

## Правила начисления

| Условие | Действие | Куда |
|---|---|---|
| канал `Shop` | +10% от суммы | `bonus` |
| канал `Online` | +17% от суммы | `bonus` |
| `amount > 300` | +30% от суммы **вместо** 10/17 | `bonus` |
| `amount < 20` | −10% от суммы | `money` → `bankCommission` |

### Важно: приоритет бонуса

```
amount > 300  →  30%   (канал Shop/Online значения НЕ имеет)
иначе Shop    →  10%
иначе Online  →  17%
```

То есть покупка 400 ₽ онлайн = **30%**, а не 17%+30%. Это решение зафиксировано тикетом T-002.

### Важно: комиссия не исключает бонус

`amount < 20` не отменяет 10%/17% — платёж получает **и** бонус, **и** комиссию.
Диапазоны `< 20` и `> 300` не пересекаются, поэтому одновременно EnhancedBonus и
BankCommission сработать не могут.

### Округление

Все денежные значения округляются до 2 знаков, `RoundingMode.HALF_UP`.
Округляется **результат** процента, не сама сумма.

```
покупка 199.99 онлайн
бонус = 199.99 * 0.17 = 33.9983  →  34.00
```

## Переходы состояний (State pattern)

```
                     ┌──────────────────────┐
  controller ───────►│  InitPaymentState    │
                     └──────────┬───────────┘
                          канал │
                ┌───────────────┴───────────────┐
                ▼                               ▼
   ┌───────────────────────┐        ┌─────────────────────────┐
   │ RegularPaymentShopState│        │ RegularPaymentOnlineState│
   └───────────┬───────────┘        └───────────┬─────────────┘
               │                               │
               └───────────────┬───────────────┘
                               │ amount > 300 ?
                 ┌─────────────┴─────────────┐
                ДА                           НЕТ
                 ▼                            │
      ┌──────────────────┐                   │
      │EnhancedBonusState│                   │
      └────────┬─────────┘                   │
               └─────────────┬────────────────┘
                             │ amount < 20 ?
               ┌─────────────┴─────────────┐
              ДА                           НЕТ
               ▼                            ▼
    ┌────────────────────┐        ┌────────────────────┐
    │BankCommissionState │        │  FinishPaymentState│
    └─────────┬──────────┘        └─────────┬──────────┘
              └────────────┬────────────────┘
                           ▼
                 FinishPaymentState
                 (сохранение в БД)
```

Каждое состояние делает **ровно одно** и возвращает **следующее** состояние.

## API

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/api/payment/{Shop\|Online}/{amount}` | 200 без тела |
| GET | `/api/money` | 200, текущий баланс денег |
| GET | `/api/bankAccountOfEMoney` | 200, бонусный баланс |
| GET | `/api/commission` | 200, накопленная комиссия банка |

### Ошибки

| Ситуация | HTTP | Пример сообщения |
|---|---|---|
| сумма не число | 400 | `Некорректный формат суммы: abc` |
| сумма ≤ 0 | 400 | `Сумма покупки должна быть положительной: -5` |
| канал не `Shop`/`Online` | 400 | `Неизвестное место покупки: Market` |
| не хватает денег | 400 | `Недостаточно средств: нужно 500.00, доступно 120.00` |
