# Доменные правила — source of truth

Если код противоречит этому документу — баг в коде.
Если этот документ противоречит бизнес-требованию — баг в документе, нужен тикет.

## Счета клиента

| Счёт | Что это | Меняется |
|---|---|---|
| `money` | наличные / безнал | −`amount` при покупке, −комиссия |
| `bonus` | бонусный счёт (e-money) | +бонус при покупке |
| `bankCommission` | накопленная комиссия банка | +комиссия при покупке |

Начальные значения задаются в `application.yml` (`app.initial.*`), а не хардкодятся.

## Правила начисления

| Условие | Действие | Куда |
|---|---|---|
| канал `Shop` | +10% от суммы | `bonus` |
| канал `Online` | +17% от суммы | `bonus` |
| `amount > 300` | +30% от суммы **вместо** 10/17 | `bonus` |
| `amount < 20` | −10% от суммы | `money` → `bankCommission` |

### Важно: приоритет бонуса

```
amount > 300  →  30%   (канал Shop/Online значения НЕ имеет)
иначе Shop    →  10%
иначе Online  →  17%
```

То есть покупка 400 ₽ онлайн = **30%**, а не 17%+30%. Это решение зафиксировано тикетом T-002.

### Важно: комиссия не исключает бонус

`amount < 20` не отменяет 10%/17% — платёж получает **и** бонус, **и** комиссию.
Диапазоны `< 20` и `> 300` не пересекаются, поэтому одновременно EnhancedBonus и
BankCommission сработать не могут.

### Округление

Все денежные значения округляются до 2 знаков, `RoundingMode.HALF_UP`.
Округляется **результат** процента, не сама сумма.

```
покупка 199.99 онлайн
бонус = 199.99 * 0.17 = 33.9983  →  34.00
```

## Переходы состояний (State pattern)

```
                     ┌──────────────────────┐
  controller ───────►│  InitPaymentState    │
                     └──────────┬───────────┘
                          канал │
                ┌───────────────┴───────────────┐
                ▼                               ▼
   ┌───────────────────────┐        ┌─────────────────────────┐
   │ RegularPaymentShopState│        │ RegularPaymentOnlineState│
   └───────────┬───────────┘        └───────────┬─────────────┘
               │                               │
               └───────────────┬───────────────┘
                               │ amount > 300 ?
                 ┌─────────────┴─────────────┐
                ДА                           НЕТ
                 ▼                            │
      ┌──────────────────┐                   │
      │EnhancedBonusState│                   │
      └────────┬─────────┘                   │
               └─────────────┬────────────────┘
                             │ amount < 20 ?
               ┌─────────────┴─────────────┐
              ДА                           НЕТ
               ▼                            ▼
    ┌────────────────────┐        ┌────────────────────┐
    │BankCommissionState │        │  FinishPaymentState│
    └─────────┬──────────┘        └─────────┬──────────┘
              └────────────┬────────────────┘
                           ▼
                 FinishPaymentState
                 (сохранение в БД)
```

Каждое состояние делает **ровно одно** и возвращает **следующее** состояние.

## API

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/api/payment/{Shop\|Online}/{amount}` | 200 без тела |
| GET | `/api/money` | 200, текущий баланс денег |
| GET | `/api/bankAccountOfEMoney` | 200, бонусный баланс |
| GET | `/api/commission` | 200, накопленная комиссия банка |

### Минимальная сумма покупки

Операция дешевле **0.10 ₽** отклоняется с HTTP 400.

Причина не в «красоте числа». При сумме меньше 0.05 ₽ и бонус, и комиссия
округляются до нуля: деньги списываются, а пользы нет ни клиенту, ни банку.
Порог 0.10 ₽ — наименьшее круглое значение, при котором обе величины ненулевые
(бонус и комиссия = 0.01).

Значение задаётся в `application.yml` → `app.min-amount`.

### Порядок проверок суммы

Знак проверяется **раньше** минимума, чтобы отрицательное значение отвергалось
с сообщением «должна быть положительной», а не «меньше минимальной».

Побочный эффект, пока не решённый: сумма вида `0.001` округляется контроллером
до `0.00` **до** входа в состояния, поэтому отвергается проверкой знака
с сообщением про `0.00`. Открыт вопрос в T-008.

### Ошибки

| Ситуация | HTTP | Пример сообщения |
|---|---|---|
| сумма не число | 400 | `Некорректный формат суммы: abc` |
| сумма ≤ 0 | 400 | `Сумма покупки должна быть положительной: -5` |
| сумма < 0.10 | 400 | `Сумма покупки меньше минимальной: 0.01, минимум 0.10` |
| канал не `Shop`/`Online` | 400 | `Неизвестное место покупки: Market` |
| не хватает денег | 400 | `Недостаточно средств: нужно 500.00, доступно 120.00` |

## Сценарная таблица

Эталонные значения, зафиксированные тестом `PaymentApiTest.purchaseScenario`.
Стартовое состояние: `money = 10000.00`, `bonus = 0.00`, `bankCommission = 0.00`.

| Канал | Сумма | Бонус | Комиссия | Остаток | Что проверяет |
|---|---|---|---|---|---|
| Shop | 100.00 | 10.00 | 0.00 | 9900.00 | базовая ставка магазина |
| Online | 100.00 | 17.00 | 0.00 | 9900.00 | базовая ставка онлайна |
| Shop | 15.00 | 1.50 | 1.50 | 9983.50 | бонус **и** комиссия одновременно |
| Online | 15.00 | 2.55 | 1.50 | 9983.50 | то же для онлайна |
| Shop | 19.99 | 2.00 | 2.00 | 9978.01 | округление у нижней границы |
| Shop | 20.00 | 2.00 | 0.00 | 9980.00 | ровно 20 — комиссии нет |
| Online | 20.00 | 3.40 | 0.00 | 9980.00 | ровно 20 онлайн |
| Online | 199.99 | 34.00 | 0.00 | 9800.01 | округление по результату: 33.9983 → 34.00 |
| Shop | 299.99 | 30.00 | 0.00 | 9700.01 | ещё обычный тариф: 29.999 → 30.00 |
| Shop | 300.00 | 30.00 | 0.00 | 9700.00 | ровно 300 — **ещё** 10%, не 30% |
| Online | 300.00 | 51.00 | 0.00 | 9700.00 | ровно 300 онлайн — 17%, не 30% |
| Shop | 300.01 | 90.00 | 0.00 | 9699.99 | 300.01 — уже enhanced: 90.003 → 90.00 |
| Online | 400.00 | 120.00 | 0.00 | 9600.00 | enhanced независим от канала |
| Shop | 0.10 | 0.01 | 0.01 | 9999.89 | минимальная сумма: обе величины ненулевые |

Ключевые границы, которые обязаны остаться в таблице при любых изменениях:
**19.99 / 20.00** (комиссия) и **300.00 / 300.01** (enhanced).

Три строки, которые обязаны различаться — иначе тест ничего не проверяет:

- `Shop 300.00` → **30.00** (10% от 300)
- `Online 300.00` → **51.00** (17% от 300), *не* 90.00
- `Shop 300.01` → **90.00** (30%), *не* 30.00

Если эти строки стали одинаковыми, то сломан тест, а не логика.
